Notation: `P = 998244353`. A tag is `f(x)=a1*x+b1`. "g after f" means `g(f(x))`.

## 1. Composition of tags
Let the pending tag be `f(x)=a1*x+b1` and the newer tag `g(x)=a2*x+b2`. An element must see `f` first, then `g`:

`g(f(x)) = a2*(a1*x+b1)+b2 = (a2*a1)*x + (a2*b1+b2)`.

So `compose(g,f) = (a2*a1, a2*b1+b2)`; this is again affine, so one pair per block suffices. Identity is `(1,0)`: `compose(g,id) = (a2, a2*0+b2) = g` and `compose(id,f) = (a1, b1) = f`.
Associativity (needed because tags may be combined in groups): `h(g(f(x)))` is function composition, which is associative; so the combined tag does not depend on grouping, only on order.
Modular mode: all of `a,b,x` may be replaced by residues because `+` and `*` respect congruence mod P.

## 2. Non-commutativity
`f(x)=x+3` (`(1,3)`), `g(x)=-x` (`(-1,0)`).
- `+3` then negate: `compose(g,f) = (-1*1, -1*3+0) = (-1,-3)`, i.e. `-x-3`.
- negate then `+3`: `compose(f,g) = (1*-1, 1*0+3) = (-1,3)`, i.e. `-x+3`.
At `x=10`: `-13` versus `-7`. Hence the order `new_a=a2*a1, new_b=a2*b1+b2` cannot be swapped (swapping gives `a1*b2+b1`, which equals `a2*b1+b2` only when `(a2-1)*b1 = (a1-1)*b2`, false here: `-2*3 != 0`).

## 3. Sum update
Block of length `L`, logical values `x_1..x_L`, `S=Σx_i`. After applying `(a,b)`:
`S' = Σ(a*x_i+b) = a*Σx_i + b*L = a*S + b*L`.
Reduce mod P (normalising negative residues): `S' mod P = (a mod P)(S mod P) + (b mod P)(L mod P) mod P`. This needs only `S`, `L`, no per-element data, so a full-block update costs O(1). The last block uses its real `L`.

## 4. Extrema under gain a in {-1,0,1}
Let `m=min x_i`, `M=max x_i`.
- `a=1`: `x -> x+b` is strictly increasing, so order is preserved: `min'=m+b`, `max'=M+b`.
- `a=0`: all values become `b`: `min'=max'=b`.
- `a=-1`: `x -> -x+b` is strictly decreasing: `x_i <= x_j` iff `-x_i+b >= -x_j+b`. The smallest new value comes from the largest old value: `min' = -M+b = a*M+b`, `max' = -m+b = a*m+b`. The roles swap. Using `a*m+b` for the new min would be wrong whenever `m<M`: e.g. `{1,5}`, `a=-1,b=0`: true min `-5 = a*M+b`, not `a*m+b = -1`.
General `a<0`: same argument (strictly decreasing), so the swap holds for any negative gain. The project's contract restricts exact mode to `{-1,0,1}` (INTERFACE.md); see D3 for why exact extrema cannot be combined with a modular sum for arbitrary gains.

# D5 - Maximum lazy push-downs

Author: Anagh Singla - Roll number 250001006 - Member 5, Adversary. Project 7, CS253/MA253.

## Required statement

Construct an operation sequence that achieves the maximum number of push-downs per operation, and prove the bound.

## Counting convention and upper bound

The shared counter counts one push-down when one internal node propagates a
nonidentity pending tag to both children. Two child applications count as ONE
push-down. Identity checks, fully covered nodes, and leaves do not count.
Assume the existing recursive midpoint tree and contiguous half-open ranges.

A node is pushed only when the requested interval partially covers it. At a
fixed depth, disjoint nodes partition the array. All intersected nodes between
the two boundary nodes are fully covered. Thus at most two nodes per depth are
partial, and at depth zero there is at most one. If the tree height is h, there
are at most 1 + 2(h-1) = 2h-1 push-downs in one update or query, for h >= 1.
For n=0 or n=1, the bound is zero. Since h=ceil(log2(n)), this is O(log n).
This counts pushes, not all visited nodes or child tag compositions.

## A sequence attaining the bound

For n=2^h with h>=2, choose one cut inside a deepest leaf pair in the left
half and another in the right half. Our generator uses l=1, r=n/2+1;
query [l,r) cuts one node in each half at every internal depth below the root.
There are exactly 2h-1 partially covered internal nodes. For n=2, use [0,1).

Repeat the following two-operation cycle:

1. Update [0,n) by (a,b)=(0,c), where -31<=c<=31.
2. Query [l,r).

The update replaces the root tag with a nonidentity reset. Whenever it is
pushed, composing it after any child tag again produces (0,c), which cannot be
identity. Inductively every partial node carries a nonidentity reset when
visited. Consequently every possible push in the query actually happens.
The reset itself does zero pushes. Every probe attains the maximum; an
even-q workload has (q/2)*(2h-1) total pushes, hence Theta(q log n) work.
This does not claim that every operation, including the priming resets,
performs the maximum. Repeating narrow queries without re-priming would fail.

For arbitrary n>=2 let L=ceil(n/2), R=floor(n/2), and H(s)=ceil(log2(s)),
with H(1)=0. The exact maximum is M(n)=1+H(L)+H(R).
An interval cutting both root children pushes the root once; inside each child
only one interval boundary is present, so it can push at most the child's height.
An interval contained in one child has at most 1+M(child) pushes, and
M(child)<=2*H(child)-1. The child heights differ by at most one, so
1+M(child)<=1+H(L)+H(R). These cases exhaust all intervals.
A deepest cut in each nonsingleton child attains H(L) and H(R), because midpoint
splitting always has a deepest leaf pair on the leftmost descent.
A singleton child contributes zero. The generator chooses these cuts; a reset
makes all their pending tags nonidentity, so it attains M(n).
For n=1000000 both child heights are 19, hence M(n)=39. For powers of two,
M(n)=2*h-1. Empty/singleton arrays have M(n)=0.

## Where this is used

`adversary/module.cpp`: `maximum_push_range` chooses the query boundaries,
`deepest_boundary` finds a deepest cut, and `generate` emits the reset/probe cycle.
`tests/adversary_test.cpp`: `exact_push_counts` checks every small range and both
queries and updates against the power-of-two formula. `adversary/replay_check.cpp`
checks M(n) on every primed query, plus independent uniform-array answers,
A/B agreement and final invariants at n=q=1000000 in both modes.

## Other required adversarial targets

Alternating negative gains start with asymmetric extrema (-19 and 37). A whole
query immediately after (-1,7) observes swapped extrema; it does not push the
root tag. Full updates (1,3), (-1,-5) then accumulate before a point query,
exposing composition order. Negation reverses order: min'=-max+b,
max'=-min+b. Reset/overlap/endpoint/empty probes recur every 16 operations.
Shift then negate maps x to -x-3, whereas negate then shift maps x to -x+3.

The block-friendly family updates/queries one block aligned to the automatic
ceil(sqrt(n)) block size. It includes the final short block. B uses exactly one
full-block access and zero partial-element accesses per operation. A follows
boundary paths. This is a candidate for a B advantage, not a measured timing
claim: caches, constants and n can change the result. An overridden B block
size must be reset to zero before using this family's alignment assumption.

The width sweep includes 1, n, the configured width, powers of two, and widths
around the automatic block size. Each width gets eight operations covering
left/right endpoints, a shifted boundary, and a seeded position. Both modes
are supported. Modular sweeps include INT64_MIN/MAX coefficients to test
normalization before multiplication; exact mode never uses such gains.

## Safety, reproducibility and scope

Initial absolute values are at most 1000. Exact gains are -1, 0, or 1 and
offsets have absolute value at most 31. After q updates both values and any
composed offset are bounded by 1000+31*q. Configurations violating the int64
bound are rejected. Generation is O(n+q+log n) time and O(n+q+log n) space.
Empty arrays generate empty queries; zero operations are supported. Output
always contains exactly the requested number of operations, including the priming resets.

The seed is stored in Workload. std::mt19937_64 raw outputs plus explicitly
specified remainder operations avoid library-dependent random distributions.
Persist the complete CS253_V1 file along with seed, target, n, q, width and
generator revision; a seed alone is not a long-term reproduction artifact.
The tests export the entire workload on differential failure. Their independent
array is test-only; they do not implement or replace Member 4's Oracle module.

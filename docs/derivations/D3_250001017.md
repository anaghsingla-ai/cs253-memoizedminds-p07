## 1. Why `(sum, length, k)` is not enough for a lazy range-modulo tag

Let a range contain nonnegative integers `x_1, ..., x_L`, and let one update replace every value by `x_i' = x_i mod k`, where `k > 0`.

Suppose a node stores only its old sum `S = sum(x_i)` and its length `L`. A conventional lazy-tag mapping based only on this information would need a function `F(S, L, k)` that returns the new range sum. Such a function must give the same answer for any two ranges with the same `S`, `L` and `k`.

Consider the two length-two ranges:

- `A = [1, 5]`, whose sum is 6;
- `B = [3, 3]`, whose sum is also 6.

Choose `k = 4`. After applying modulo element by element:

- `A` becomes `[1, 1]`, with sum 2;
- `B` becomes `[3, 3]`, with sum 6.

The old information `(S, L, k)` is `(6, 2, 4)` in both cases, but the new sums differ. The same counterexample also works when the stored sum is reduced modulo the project's checksum prime `P = 998244353`, because 2 and 6 remain distinct residues.

Therefore no function of only the old sum, the length and `k` can determine the new sum for every possible range. In particular, modulo is not representable by a single ordinary lazy tag whose application updates a node's sum using only those stored fields. The obstruction is lost information: the sum does not reveal how the values are distributed relative to `k`.

This is a claim about the stated summary `(sum, length)`; it does not say that range modulo is impossible with every data structure or every richer node summary.

## 2. A restricted variant that is still efficient

Now consider a different API that supports only:

1. `range_mod(l, r, k)`: replace every `x_i` in `[l, r)` by `x_i mod k`, with `k > 0`;
2. `assign(p, v)`: set one position to `v`;
3. `range_sum(l, r)`: return the sum on `[l, r)` (or its residue modulo `P`).

Assume all values are nonnegative integers; every initial value and every assigned value lies in `[0, C]`; `C` is a fixed upper bound for the workload; and ranges use zero-based half-open indexing.

This restricted variant does not support arbitrary affine updates and does not use lazy affine tags.

Build a segment tree in which each node stores the exact maximum value in its interval and the interval sum (stored exactly if the numeric type permits, or modulo `P` for checksums).

For a modulo update, recurse only into intersecting nodes whose stored maximum is at least `k`:

```text
range_mod(node, interval, query_range, k):
    if interval is disjoint from query_range:
        return
    if node.maximum < k:
        return                    // every value here is unchanged
    if interval is a single position:
        value = value mod k
        node.maximum = value
        node.sum = value
        return
    range_mod(left_child,  ..., query_range, k)
    range_mod(right_child, ..., query_range, k)
    pull node.maximum and node.sum from its children
```

The test `maximum < k` is safe because every value in that node is then smaller than `k`, so every value is unchanged by modulo. If a node intersects only part of the query, its maximum may include positions outside the query; that can cause extra descent, but cannot cause an incorrect skip. The maximum and sum are recomputed on the path back to the root.

A point assignment updates its leaf and its ancestors in `O(log(n + 1))` time. A range-sum query is the ordinary segment-tree query and also takes `O(log(n + 1))` time.

## 3. Halving lemma

**Lemma.** If a modulo operation with positive `k` actually changes a nonnegative integer `x`, then its new value is strictly less than `x / 2`.

**Proof.** A change occurs only when `x >= k`; if `x < k`, then `x mod k = x` and no change occurs. For `x >= k`, split into two cases.

- If `k <= x/2`, then `0 <= x mod k < k <= x/2`.
- If `k > x/2`, then `x/2 < k <= x`, so the quotient is exactly one and `x mod k = x - k < x/2`.

In either case, the changed value is strictly smaller than half its previous value. `\square`

## 4. Amortised bound on the number of changed leaves

Call the time between the initialisation of one array position and its next point assignment a *value lifetime*. The initial array contributes `n` lifetimes. Each point assignment starts at most one additional lifetime, and there are at most `m` assignments among `m` total operations. Thus there are at most `n + m` lifetimes.

At the start of every lifetime, the value is at most `C`. By the halving lemma, after `t` effective modulo changes during that lifetime, its value is strictly less than `C / 2^t`. Since values are nonnegative integers, after at most `floor(log2 C) + 1` effective changes the value must be zero; zero cannot be changed by another positive-modulus operation. Therefore, for `C >= 1`, each lifetime has `O(1 + log C)` effective modulo changes. Summing over all lifetimes gives

`T = O((n + m)(1 + log C))`

for the total number `T` of changed leaves across the entire operation sequence. For `C >= 2`, this is conventionally written as `T = O((n + m) log C)`. If `C = 0`, no modulo operation changes a value; if `C = 1`, each lifetime has at most one effective change, so `T = O(n + m)`.

The point-assignment count is already bounded by `m`; an assignment may restore a large value, but it starts a new lifetime and is therefore charged separately rather than invalidating the halving argument for the previous lifetime.

## 5. Total running time

For one range-modulo operation that changes `t` leaves, max-pruning visits the segment-tree paths leading to those leaves, plus at most `O(log(n + 1))` boundary nodes caused by the two ends of the query interval. The union of `t` root-to-leaf paths contains at most `O((t + 1) log(n + 1))` nodes. Consequently, its cost is `O((t + 1) log(n + 1))`.

Across the whole workload:

- all range-modulo operations cost `O((m + T) log(n + 1))` in total;
- all point assignments cost `O(m log(n + 1))`;
- all range-sum queries cost `O(m log(n + 1))`.

Combining these bounds and substituting the bound on `T`, for `C >= 2` we obtain

`O((n + m) log(n + 1) log C)`.

For `C <= 1`, the bound is `O((n + m) log(n + 1))`. Segment-tree storage is `O(n)`. For `n >= 2`, the conventional notation `log(n + 1)` may be written as `log n`; the `n + 1` form also covers the constant-time `n = 1` edge case.

## 6. Conclusion and connection to Project 7

The first result explains why a range-modulo update cannot be treated like the affine lazy updates in Structures A and B when the node summary contains only sum and length: two ranges with identical summaries can require different new sums. The second result shows that this does not make the restricted modulo problem intractable. A segment tree storing exact maxima can prune every interval whose values are all below `k`, and the halving lemma bounds how often a leaf can force descent between point assignments.

This is a separate restricted variant: range modulo, point assignment and range sum only. It is not a claim that the main calibration simulator should replace its affine lazy segment tree or square-root decomposition with this structure.
